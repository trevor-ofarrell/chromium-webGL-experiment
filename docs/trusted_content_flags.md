# Trusted Content Flags

Date: 2026-05-22

Unsafe behavior is gated by both `--viewer-app-url` and `--viewer-trusted-content`. The fork keeps reserved experiment gates as no-ops unless a source implementation exists, and maps the relaxed WebGL validation experiment to Chromium's pass-through command decoder switch. Each aggressive run must be compared against stock Chromium and the fork default profile from the same Chromium revision.

Chromium WebGPU/Dawn launch flags are also treated as trusted experiments. The benchmark and trace runners reject `--use-webgpu-adapter`, `--enable-dawn-features`, `--disable-dawn-features`, `--enable-features`, and `--disable-features` unless both `--viewerMode` and `--viewerTrustedContent` are present. The trusted experiment matrix can add Dawn probes through `-Renderer webgpu -IncludeWebGpuDawnExperiments`, including D3D11 adapter, flush, fence, thread-safe queue-wait, discard, upload-path, and mappable backend-buffer auto-map toggles, standalone `skip_validation` / `disable_robustness`, Dawn `blob_cache_hash_validation` disablement for shader/pipeline cache-overhead attribution, and D3D11 plus `skip_validation` / `disable_robustness` interaction rows for trusted draw-call/glTF attribution; Chromium feature probes through `-Renderer webgpu -IncludeWebGpuChromiumFeatureExperiments`, including `RemoveGPULegacyIPC`, `WebGPUUseHLSL2021`, and `WebGPUEnableRangeAnalysisForRobustness` disablement; and upload/command-buffer probes through `-Renderer webgpu -IncludeWebGpuUploadExperiments`. Every copyExternalImage upload-row and D3D11 copyExternalImage interaction row also passes `--viewer-reject-webgpu-cpu-texture-fallback`, so a rebuilt benchmark fails instead of treating CPU readback/upload fallback as a performance candidate. The upload fast-path row combines D3D11, DXC, delayed flush, unmonitored fence, mapped-buffer clear skip, Dawn validation/robustness skips, Chromium IPC/HLSL/command-slice flags, D3D staging-upload selection, robustness range-analysis disablement, Blink pipeline/command-label/queue/submit/canvas/writeTexture/use-counter skips, redundant setPipeline, setBindGroup, buffer-state, and render-state skips, CPU-fallback rejection, and resource-label skip; it is never scheduled for large-static or glTF-only blocker groups. Targeted trace/benchmark runs can also pass the source-backed `--viewer-reject-webgpu-cpu-texture-fallback` diagnostic to fail instead of using the `CopyFromCanvasSourceImage` CPU readback/upload fallback, which helps reject contaminated WebGPU texture-streaming evidence. Rebuilt WebGPU diagnostic traces can additionally pass `--viewer-trace-webgpu-queue` to emit Blink `GPUQueue::*` attribution slices; normal benchmark runs keep this off so source trace instrumentation is not paid on the default performance path. It records the exact `browser_flags` and per-experiment `required_browser_flags`, validates those raw flags against the checkout's Dawn toggle registry, Chromium GPU feature declarations, and WebGPU adapter parser before WebGPU experiment dry-runs or live runs launch, and validates the effective flags before accepting raw result JSON. Blob-cache hash-validation runs additionally record viewer origin/cache eligibility and are rejected under file-mode or explicit `disable_blob_cache` launches, because those would prevent Dawn's blob cache from participating and would contaminate the shader/pipeline-cache attribution. WebGPU trusted matrix runs can also use `-DisableGpuTiming`; the completion pipeline passes this for the WebGPU Dawn matrix when official WebGPU timing is disabled so timestamp queries do not recreate known device-loss failures.

Clarification: the redundant `setPipeline`, zero-dynamic-offset `setBindGroup`, and buffer-state skips are part of the pass-encoding pipeline/submit experiment family, not the texture-streaming upload fast path. Texture-upload rows remain focused on queue, canvas, copyExternalImage, writeTexture, upload-backend, use-counter, and CPU-fallback behavior.

The suite validator, strict comparison report generator, and candidate speedup analyzer repeat the trusted-content check on raw JSON. A stale or hand-edited result with a trusted-only viewer metadata field or raw experiment browser flag is rejected unless it also records `viewer_mode=true` and `viewer_trusted_content=true`, so unsafe rows cannot be promoted after bypassing the benchmark launcher.

There is intentionally no separate trusted flag for skipping post-creation WebGPU `.label` setter calls. The source-backed setter bypass is part of `--viewer-skip-webgpu-resource-labels`; under trusted local viewer launches it short-circuits requestDevice/defaultQueue labels before Blink device/queue wrapper construction, skips descriptor-backed texture and canvas current-texture wrapper label UTF-8 conversion, clears the Blink wrapper label, skips Dawn native label propagation, and avoids carrying async render/compute pipeline descriptor labels through pipeline-creation callbacks.

`--viewer-skip-webgpu-command-labels` also clears the JS-visible Blink wrapper labels created for per-frame command encoders, render/compute pass encoders, render-bundle encoders, finished render bundles, and command buffers. This keeps command-label skipping scoped to command submission objects while leaving resource labels controlled by `--viewer-skip-webgpu-resource-labels`.

The shader-module flags isolate two Blink-side startup/setup costs that showed up in shader-heavy WebGPU traces: `--viewer-skip-webgpu-shader-source-null-check` removes the trusted WGSL NUL scan before Dawn shader-module creation, and `--viewer-skip-webgpu-shader-memory-accounting` removes Tint's external-memory estimate for shader modules. Both are trusted-only attribution probes and are included in the aggressive D3D11 pipeline/submit fast-path row, but neither is retained until a rebuilt same-revision suite improves throughput and tails without device loss.

The benchmark runner's explicit reused-profile mode is for warmed WebGPU cache attribution, not for default evidence. `--userDataDir` is accepted only under `benchmarks/tmp` and requires `--profileCacheKey`; result JSON records the profile-cache mode/key, and candidate/strict comparison gates require stock and fork rows to match that key before a warmed-cache run can be compared.

Raw compositor GPU-resource browser flags are also trusted-only. The benchmark and trace runners reject `--enable-gpu-memory-buffer-compositor-resources`, `--ui-enable-zero-copy`, and `--enable-gpu-rasterization` unless both `--viewerMode` and `--viewerTrustedContent` are present. The trusted WebGL2 matrix can add them through `-IncludeWebGlCompositorExperiments`, including a combined row with `--viewer-zero-copy` to test the current zero-copy tail-latency blocker.

Raw frame-pacing browser flags are trusted-only as well. The benchmark and trace runners reject `--disable-frame-rate-limit` and `--disable-gpu-vsync` unless both viewer trust gates are present. The trusted matrix can add standalone and combined frame-pacing rows through `-IncludeFramePacingExperiments`; these rows are attribution candidates for FPS caps, presentation latency, and tail variance, not default optimizations.

When `-Renderer webgl2`, `-IncludeZeroCopy`, and `-AngleBackend d3d11` are selected together, the trusted matrix also emits an isolated D3D11 plus `--viewer-zero-copy` row. That row is intentionally separate from relaxed WebGL validation so the current zero-copy throughput/tail candidate can be attributed without changing the command decoder at the same time.
